## Known differences, ambiguities and release blockers

1. **Restart policy is deliberately explicit.** Current Fly preserves ranked identity/seed but labels every restart as training (F L915/L925/L953). Snake keeps that accounting policy with truthful copy, and resets only incomplete local state. Server TTL and authorization are not renewed. A new identity/debit would be a product-policy change, not a silent bugfix.
2. **Timeout does not mean “not spent.”** F L1005/L923 and sponsor messages imply no debit on network failure, but a server may have committed before the response was lost. Snake needs request identity and read/reconcile support; never issue a second start/claim merely because the first response timed out. A finish timeout may be accepted server-side; retain result and reconcile at-most-once settlement. The Fly frontend has no explicit attempt-status recovery endpoint.
3. **Participant changes and stale responses need stronger fencing.** F hub read checks participant; F start checks only host epoch after its request; sponsor has no host/participant fence; finish calls `profile().id` at finish rather than binding the starting profile. Snake must pin run identity and invalidate responses when host/profile/session changes. No late response may reactivate a disposed game or update another account.
4. **Training and failed results must not imply accepted records/rewards.** F L893 uses `max(hub.best_score,model.score)` for result record even in training/failed finish; F L1262 derives new record from local score and uses `points_awarded || reward`. Snake uses exact accepted score/best/award, preserving valid zero. Sharing is offered for confirmed record only.
5. **Unlimited training availability differs intentionally.** Current Fly still gates local training on Hub availability (F L996), although it debits nothing. Snake local training should be available offline/without a ranked adapter; unavailable live ranking remains clearly unavailable.
6. **3 normal / 24h + 2 sponsor is policy, not verified SQL.** Current UI proves labels/counters and the 2-claim cooldown message, but not server cycle anchoring, grant security, atomic accounting, retry behavior, rollover, or independent game isolation. Publish remains blocked until Snake backend contract/migrations and live verification cover these points. Source code must not fabricate a successful ranked backend when integration is absent.
7. **Current Fly payload is aggregate-only.** Do not claim authoritative deterministic replay validation merely because a browser state hash or seed exists. Define Snake server validation and limitations separately; browser checks cannot establish honesty of client-owned inputs. Ranked restart validity must be covered by this contract.
8. **Visual and lifecycle acceptance is pending implementation QA.** Test real menu routes (not just fixtures), desktop embedded/native fullscreen/Escape, mobile portrait/landscape/D-pad/orientation/pseudo fullscreen, popup/Hub leave, profile change, visibility/BFCache, blocked sponsor tab, large result/leaderboard text, zero awards, concurrent clicks and lost responses. Check no surviving timer/RAF/audio owner and no physics change after viewport/effects settings. Daily Challenge/King must remain absent.

## Fixed-session mapping boundary

`arcade/snake-next/gate-one/session.js` L11–74 supplies `TunnelSession`, deterministic advance/hash/progression summaries and paired tunnel edges. `cancelPortal()` L45 intentionally leaves canonical traversal frozen during pause; `transfer()` L46 rejects whole-body transfer. `arcade/snake-next/simulation/clock.js` L1–26 owns the main-thread fixed accumulator and injectable timer driver, detects excessive scheduler lag and clears debt on pause/resume. `arcade/snake-next/forest-training/session.js` L7–10 supplies current Focus/Harvest/Rush durations; L138–153 owns food score/combo and terminal transitions.

Product shell owns account/menu/backend/lifecycle orchestration around those existing modules. Simulation retains run state; presentation reads snapshots. Ranked IDs, attempt counters and awards never become gameplay rules. Training/ranked must instantiate the same approved session/rules and differ only in run metadata and backend admission/settlement.
