# Mushroom Fly: постоянные правила UI

## Архитектура

- Main Menu — отдельная Title Scene с текущим fantasy background, логотипом и героем. Это не остановленный игровой кадр.
- Инициализация, reload и восстановление страницы открывают Main Menu, независимо от остатка попыток. Нулевой остаток сам по себе не открывает exhaustion modal.
- Primary slot берёт состояние из существующего hub: обычная/зачисленная попытка → «Играть»; ноль попыток и sponsor available → «Попытка от спонсора»; иначе тренировка. Зачисление спонсора использует существующий RPC.
- Render и collision колонн используют одну world geometry и alpha-силуэт. Концы шляпок совпадают с границами генерируемого gap; camera/DPR не меняют физику и hitbox. Граница движения героя учитывает его реальный render pose, а не отдельный отступ от пола.
- Размер gameplay stage стабилен при переходах между меню, игрой и результатом. Таблица лидеров не растягивает сцену.
- Внешний header показывает попытки, лучший счёт и место. В Main Menu эти показатели не дублируются.
- Кнопка «Рейтинг», Daily Challenge и King of the Day удалены; UI-задачи не должны их возвращать.
- Нижний ряд Main Menu: компактный Sound, более широкие «Настройки», компактный Fullscreen. Одинаковая высота и материал. Основное действие визуально доминирует.
- Подпись «3 попытки каждые 24 часа · тренировка без ограничений» показывается только в Main Menu. Читаемый кегль, тень и лёгкое локальное затемнение.

## Адаптация

- Ориентир — размеры игрового контейнера, а не только ширина браузера. Запрещено масштабировать весь UI через transform: scale.
- Desktop tutorial: цельная панель, три основные карточки и сетка усилений 3×2. Шесть колонок допустимы только на просторном fullscreen с читаемыми описаниями.
- У усилений всегда доступны названия и короткие объяснения. Нельзя скрывать объяснения ради отсутствия прокрутки.
- Desktop settings: две сбалансированные колонки «Звук» и «Игра», использующие всю ширину панели.
- На узком portrait допустимы игровые переключатели разделов обучения/настроек; активный раздел занимает всю ширину. Внутренняя прокрутка предпочтительнее уменьшения текста.
- Низкий landscape сохраняет читаемые шрифты, прокручиваемую область содержания и доступные действия.
- Pause: «Продолжить» плюс «Начать заново», «Настройки», «Главное меню». На телефоне вертикальный порядок.
- Result: главный элемент — счёт. Вторичная статистика компактна; иконка возле каждого значения необязательна.

## Художественные правила

- Сохранить fantasy mushroom world, тёплый свет, тёмное дерево, золото и кремовые акценты.
- Существующая 9-slice рамка: углы и декор фиксированного масштаба, края растягиваются только вдоль своей оси. Никакой прямоугольной подложки снаружи рамки.
- Иконки: простая заполненная форма, качественный объёмный материал, мягкая фаска, читаемость в 20–24 CSS px. Не библиотечные glyphs, emoji или самодельные outline SVG.
- Каждая новая production icon создаётся отдельно с нуля; raster имеет настоящую прозрачность, чистый край и безопасные отступы.
- Reference — художественный ориентир, не исходный ресурс. Не нарезать screenshots/reference, не удалять их фон, не использовать фрагменты или общий сгенерированный sheet.
- Перед интеграцией проверять новые иконки в галерее на дереве, зелёной кнопке, тёмном фоне и checkerboard, в размерах 20/24/32/40/48 px.

## Поведение и проверка

- Real buttons, aria-label для icon-only, видимый keyboard focus, hover/pressed/disabled states. Sound отражает AudioManager; fullscreen использует существующий механизм.
- UI-задачи не меняют физику, score, PERFECT, бонусы, сложность, биомы, попытки, сезон и leaderboard backend.
- Перед правками проверять Git и делать checkpoint. Публиковать только TEST, если отдельно не разрешён production.
- Проверять embedded, fullscreen, tablet, portrait и низкий landscape; смотреть screenshots при 100%, а не только проверять отсутствие overflow. Для desktop проверять также 125% zoom.
- Наличие вкладок, отсутствие overflow и зелёные тесты сами по себе не доказывают читаемость или художественное качество.
